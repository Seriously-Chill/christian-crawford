# Motion

Real, sourced interactions — read from the site's own `style.css`, `custom-frontend.min.css`, `page-transitions.min.js`, and inline `<script>`/`<style>` blocks across all 6 captured pages (Home, Product, Innovations, Contacts, About us, News), not guessed. Every claim below has been checked for a later or higher-specificity CSS rule overriding the first match found, across all 6 pages, not just Home — the page-transition entry has a worked example of why that check matters.

**Smooth scroll.** Lenis runs site-wide — `<html class="lenis">` on every page, `lenis.min.js` its own script. The init call is explicit, inline on every page:
```js
new Lenis({ duration: 1.2, easing: (t) => Math.min(1, 1.001 - Math.pow(2, -10 * t)),
  direction: 'vertical', gestureDirection: 'vertical', smooth: true, smoothTouch: false, touchMultiplier: 2 });
```
`duration`/`easing` happen to match Lenis's own library defaults, but `touchMultiplier: 2` does not (library default is `1`) — carry that one real override, not "pure defaults."

**Ripple hover** — real, confirmed in `style.css` (identical md5 across all 6 pages, so sitewide, not homepage-only): applied via a literal `.ripple` class to the six product-category cards on Home and the Product index only, explicitly disabled inside `.other-products` cross-link sections. A `::after` pseudo-element, centered, holds `ripple.png` (`center / contain no-repeat`, `mix-blend-mode: multiply`) — fetched directly from the live site and now `public/ripple.png`; it's a soft concentric water-ripple graphic with real gray tones in its rings, not the flat single-color radial gradient an earlier pass approximated it with (that guess also missed that a *pure white* source is a no-op under `multiply` at any opacity — the real texture's gray tones don't have that problem). `.ripple:hover:after{animation:ripple .8s ease-out forwards}`, keyframes `0%{opacity:.6;scale:1}` → `100%{opacity:0;scale:3}`, gated behind `@media (hover:hover) and (pointer:fine)`. Because the rule re-declares the identical `animation` value on every `:hover`, some browsers won't restart it on repeat hovers — it can read as "fires once" even though the source code doesn't special-case that.

**Card surface is a glass tint, not a filled gray box** — correction: the actual card (`Продукція` page, element `4827d4a`) is `background-color:#FFFFFF1A; border:1px solid #FFFFFF1A; border-radius:24px; padding:24px` (`16px` on mobile) — a barely-there 10%-opacity white fill+border, not `surface-raised`/`#F8F8FA`. This treatment only reads on a colored or dark ground (same rule as `ContactForm`'s translucent inputs) — on our light `surface` pages it has to be adapted (ink-tinted, not white-tinted) rather than copied literally, or it's invisible.

**Page-transition preloader** — the header gradient at a steeper, near-vertical, full-opacity angle: `linear-gradient(174deg, primary 0% 100% secondary)`, confirmed via `.elementor-kit-6 e-page-transition{...}` in the site's kit CSS, holding a **static** (non-spinning) `70px`-wide logo mark that only fades. Real timing: `--e-page-transition-animation-duration:700ms` for the overlay itself, `--preloader-fade-duration:.5s` for the icon's own fade nested inside that. Entrance animation = fade-out (reveals the page), exit = fade-in (covers before navigating). **Worked example of why "check every occurrence" matters:** an earlier pass of this doc found a *different*, less-specific rule elsewhere in the same stylesheet — a bare `e-page-transition{background:#fff}` fallback from the transition plugin's own base styles — and concluded the overlay was flat white. That rule loses: the `.elementor-kit-6` ancestor class gives the gradient rule higher specificity, so it wins regardless of which one appears later in the source. Always resolve to the actual winning rule, not the first match.

**Sitewide staged entrance system** — real, sourced, previously undocumented: Elementor's `animated`/`animated-slow` + `fadeIn`/`fadeInUp` classes, confirmed on Home (13 elements), Innovations (7), News (3). `.animated-slow{animation-duration:2s}` (used on hero-tier content), `.animated{animation-duration:1.25s}` (used elsewhere). `fadeIn`: opacity 0→1. `fadeInUp`: opacity 0→1 **and** `translate3d(0,100%,0)→none` — slides the element's own full height, not a small nudge. Elements are staggered via an explicit per-element delay in 100ms increments (e.g. Home hero: headline 100ms → tagline 200ms → primary CTA 300ms → secondary CTA 400ms → image 500ms). This plays once, on scroll into view (or on load for above-the-fold content) — it's the site's main "premium" cue and the thing our own reveal timing under-matched most.

**Accordion (vertical expand)** — real, sourced from the About-us page's "production process"/"values" list (`.vertical-acc`): collapsed state is `height:0; overflow:hidden; margin:0`; opening transitions `height` and `margin` together, `1s cubic-bezier(0.4, 0, 0.2, 1)` (Material "standard" easing, not `ease-out`). Distinct from the ripple/entrance timings above — this is the slowest, most deliberate motion on the site, reserved for progressive-disclosure content, not decoration.

The real component is more elaborate than our current `Accordion.tsx`, found on a fuller re-read of the About page:
- Each item has a numbered label (`.number`, opacity 0.4 → 1 on hover/active) — not just a title.
- Only **one item is active at a time** (`currentIndex` state, `.active` class), navigated by dedicated up/down arrow buttons (`.vertical-acc__arrow`) alongside per-item click — not independently-toggleable items.
- The active item's expanded height is a **fixed `23px`**, not JS-measured — fragile for variable copy but real.
- **Below 880px it isn't an accordion at all** — `.vertical-acc__item .elementor-icon-box-description{height:auto!important; overflow:visible!important}` plus a horizontal `scroll-snap` wrapper and left/right arrows turn it into a swipeable carousel, one full-width item per "slide."

Carried into production as Home's "how I work" stepper (`src/components/sections/HowIWork.tsx`): numbered items at 40% opacity → 1 on hover/active, one active at a time, round up/down arrow buttons (`CircleButton`) plus per-item click, opening on the real `1s cubic-bezier(0.4, 0, 0.2, 1)` (`--duration-accordion` / `--ease-accordion`). Two deliberate departures: the open height is animated to the content's own height (a `grid-template-rows` 0fr→1fr transition) rather than the fixed `23px`, since our step copy runs two or three lines; and below `md` the steps simply stack fully open instead of becoming a swipe carousel.

Apply real interactions to the elements the source actually uses them on — don't spread the ripple to every card or button just because it exists once, and don't reach for the accordion's 1s easing anywhere faster-paced.

**Logo strip drift** — the reference's "Where to buy" strip runs edge to edge with logos cut off at both sides, i.e. a moving strip rather than a static row. Production (`EmployerMarquee.tsx`) drifts it at a slow, linear 60s loop. That speed is ours, not sourced. Because it moves on its own, it pauses on hover and has a round pause button (WCAG 2.2.2), and under reduced motion it doesn't move at all.
